# Greeting Processor Project - Full Documentation

Welcome to the documentation for the **GreetingProcessorProject**. This guide is written specifically for someone who is completely new to Kotlin and its architecture. We will go through every part of this project step by step.

## 1. What is Kotlin?
Kotlin is a modern programming language that runs on the Java Virtual Machine (JVM). It is designed to be concise, safe, and fully interoperable with Java. 

### Basic Concepts in Kotlin:
- **`fun`**: This keyword is used to declare a function (a block of code that does a specific task). `fun main()` is the entry point of a Kotlin application; it's where the program starts running.
- **`val` and `var`**: `val` is used to declare a read-only (immutable) variable, meaning its value cannot be changed once assigned. `var` is used for variables whose values can change (mutable).
- **Classes**: Kotlin is object-oriented. A `class` is a blueprint for creating objects. For example, `class MyClass` defines a new type called `MyClass`.
- **Annotations**: Annotations are a way to attach metadata (extra information) to your code. They look like `@AnnotationName`. They don't change how the code runs directly, but other tools can read them and generate code or modify behavior based on them.

## 2. Project Architecture overview
This project is not an Android app; it is a **pure Kotlin JVM project**. Its main goal is to demonstrate **Annotation Processing**.

### What is Annotation Processing?
Imagine you write some code, and you want another program to automatically write *more* code for you based on the rules you set. That's what annotation processing does. 

In this project, there are three main parts (modules):
1. **`annotations`**: This module defines the custom annotations (`@Greeting` and `@Extract`). It's just the definitions, no logic.
2. **`processor`**: This is where the magic happens. It reads the code in the `app` module, looks for the annotations defined in the `annotations` module, and generates new code automatically before the program even compiles!
3. **`app`**: This is the actual application that you run. It uses the annotations, and then uses the *code generated by the processor*.

## 3. Deep Dive into the Code

### Module 1: `annotations`
This module contains the definitions of the custom annotations.

**`Extract.kt`**
```kotlin
package org.example.annotations

@Target(AnnotationTarget.FUNCTION)
@Retention(AnnotationRetention.SOURCE)
annotation class Extract(val regex: String)
```
- `@Target(AnnotationTarget.FUNCTION)`: This means this annotation can ONLY be placed on top of functions.
- `@Retention(AnnotationRetention.SOURCE)`: This means the annotation is only visible in the source code. Once the code is compiled, the annotation disappears. This is perfect for annotation processing!
- `annotation class Extract(val regex: String)`: This creates an annotation called `@Extract` that takes a piece of text (a `regex` or regular expression) as a parameter.

**`Greeting.kt`**
```kotlin
package org.example.annotations

@Target(AnnotationTarget.FUNCTION)
@Retention(AnnotationRetention.SOURCE)
annotation class Greeting(val message: String)
```
- Similar to `Extract`, but this one takes a `message` parameter.

### Module 2: `processor`
This module contains the code that looks at the annotations and generates new code. It uses a library called **KotlinPoet** to write Kotlin code programmatically.

**`GreetingProcessor.kt`**
This processor looks for the `@Greeting` annotation.
- It finds all functions annotated with `@Greeting`.
- For each class that contains these functions, it generates a new class called a "Wrapper". If the original class is `MyClass`, it generates `MyClassWrapper`.
- The generated `MyClassWrapper` will have the same methods as the original class, but before calling the original method, it prints the message defined in the `@Greeting` annotation.

**`RegexProcessor.kt`**
This processor looks for the `@Extract` annotation.
- It finds abstract functions annotated with `@Extract`.
- It generates a new class called an "Extractor" that inherits from the original class. For example, if the original is `DataProcessor`, it creates `DataProcessorExtractor`.
- It implements those abstract methods automatically! The generated code will use the Regular Expression (Regex) provided in the annotation to extract specific parts of a text string.

### Module 3: `app`
This is where the application is run and where the annotations are actually used.

**`app/MyClass.kt`**
```kotlin
package org.example.app
import org.example.annotations.Greeting

open class MyClass {
    @Greeting("Hello from MyClass!")
    open fun sayHello() {
        println("Executing sayHello method")
    }

    @Greeting("Hello to the compute function!")
    open fun compute() {
        println("Computing something important...")
    }
}
```
- This class uses the `@Greeting` annotation. 
- Because of the `GreetingProcessor`, a class named `MyClassWrapper` is automatically generated behind the scenes!

**`app/DataProcessor.kt`**
```kotlin
package org.example.app.app
import org.example.annotations.Extract

abstract class DataProcessor(val input: String) {
    @Extract(regex = "Name: (\\w+)")
    abstract fun getName(): String ?

    @Extract(regex = "Address: (.+)")
    abstract fun getAddress(): String ?
}
```
- This abstract class uses the `@Extract` annotation.
- The `RegexProcessor` automatically generates a class called `DataProcessorExtractor` that knows how to extract the name and address from a string using those regexes!

**`app/Main.kt` (The Entry Point)**
```kotlin
fun main() {
    val myClass = MyClass()
    val wrappedMyClass = MyClassWrapper(myClass) // Using the GENERATED code!

    wrappedMyClass.sayHello() 
    // This will print:
    // "Hello from MyClass!" (From the annotation)
    // "Executing sayHello method" (From the original method)

    val input = "Name: John Address: 123 Street"
    val extractor = DataProcessorExtractor(input) // Using the GENERATED code!

    println("Name: ${extractor.getName()}")       // Prints "Name: John"
    println("Address: ${extractor.getAddress()}") // Prints "Address: 123 Street"
}
```

## Summary
The **GreetingProcessorProject** is a brilliant demonstration of metaprogramming in Kotlin. Instead of writing repetitive code to print greetings or extract regex patterns, the developer just writes an annotation, and the `processor` module writes the boring code automatically!
